## 1. Subsidy step — audit result

| Finding | Evidence |
|---|---|
| The message is `BENEFIT_EVALUATION_UNAVAILABLE` (a 503 inside the service), not a network problem | Policy-financials requests return HTTP 200; the 503 is converted to an "unavailable" benefit status |
| Two policies are "published" in the live policy table, but they are **fabricated seed records** | Document hash `e3b0c442…` is the SHA-256 of an **empty file**; approvers are placeholders (`solarsaathi-policy-team`, `-reviewer`, `-author`, `-curator`); content hash is `aaaa…`; the "sources" were never crawled (`nextDue` = year 2038). They were written by an early seeder; the seeder was deleted in `2e21736` but the rows stayed in DynamoDB |
| The integrity checks correctly refuse them | `apps/api/src/benefits/service.ts` `loadBundle` throws on bad provenance, and one bad bundle used to abort the **whole** evaluation as a 503 |
| So "make central + state show" cannot be done by making those rows work | They contain invented amounts and invented evidence. `AGENTS.md`: no fabricated policy values; changes need verification and an admin approval gate |

### Fix (done in code)
1. **Fail closed per record.** A bundle that fails verification is excluded on its own, can never contribute an amount, is
   logged by policy ID only (`POLICY_BUNDLE_FAILED_VERIFICATION`), and returns `POLICY_RECORD_FAILED_VERIFICATION`. Other
   valid rules still evaluate. Tests: mixed good + broken bundle; only a broken bundle.
2. **Plain-language reason** for that code in the UI, replacing "temporarily unavailable".
3. **"What you can do next" panel** whenever no subsidy amount is shown: keep the savings estimate, check the official
   PM Surya Ghar portal, ask for an itemised quote, check again later, links to My roofs / Help. No amounts, no eligibility claims.
4. **Cleanup tool** `scripts/policy-seed-cleanup.ts` (dry run by default; deletes only with `--apply --backup file`; needs
   at least two independent placeholder fingerprints; judged per policy record and per source partition). A copy of the 12
   live records is backed up outside the repo at `~/solarsaathi-backups/policy-table-seed-records-2026-10-11.json`.

### Getting real central AND state benefits (needs people, not code)
- A research agent builds a **policy draft pack** from official documents only (`docs/policy-drafts/`): one central
  PM Surya Ghar rule and one rule per state where an official top-up is verified, each with exact quotes, source URLs, dates and
  stacking mode (additive / conditional / capped / exclusive), plus an explicit "no verified incentive found" list.
- Two different policy administrators then register the sources, let the crawler archive them, author the drafts from the pack
  and publish (author ≠ publisher ≠ curator). Runbook: `docs/runbook-pm-surya-ghar-publication.md`.
- Until published, the app says so honestly and shows no amount.

## 2. Map outline — plan
- The automatic rotated rectangle is unreliable (Google azimuth is noisy, esp. flat roofs). Start from Google's building
  box (always contains the building) and let the user **drag the 4 corners** (keyboard nudge alternative), with Reset.
- Labels: "Automatic outline (approximate)" vs "Outline adjusted by you". The adjusted outline is saved with the analysis
  draft and used for the 3D footprint. Sizing still uses Google's modeled roof or the user's measurements, and the UI says so.

## 3. 3D panels — plan
