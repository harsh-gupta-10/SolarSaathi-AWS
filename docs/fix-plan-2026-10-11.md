# Fix plan — user-reported issues (2026-10-11)

Audit of six reported problems. Root causes were traced in code (file:line below) and key claims were spot-checked.
Nothing here relaxes the rules in `AGENTS.md`: no hardcoded subsidy amounts, deterministic calculations, explicit
roof confirmation, "space-feasible" wording.

| # | Problem | Root cause (one line) | Fix needs |

## Phase 2 — 3D roof model correctness (≈ 2–3 days)

Work in `packages/calculations/src/roof-layout.ts` (deterministic, tested) — not in React.
1. **Rotated segment rectangles**: axes from segment azimuth; solve side lengths from bounding-box W×D and ground area
   (fallback: hull of that segment's Google panel centres). Replaces shrunk axis-aligned boxes (`:181-201`).
2. **Relative heights**: subtract min `planeHeightAtCenterMeters`; if any segment lacks a height, treat all as 0 (`:200`).
3. **One building footprint**: union/hull of rotated segments (or rotated box from Phase 3) extruded to eave height in
   `roof-layout-scene.tsx:16-109`; drop the per-segment wall boxes and the magic `groundY = min.y - 3.8`.
4. **Panel placement**: keep Google panels per `segmentId`; use `assumptions.panelWidth/HeightMeters`; clip to setback
   rectangle with the existing `insideBands` check. Delete or rewrite `buildAlignedProfessionalLayout`
   (`roof-layout-viewer.tsx:41-201`) on these rules.
5. **Mounting offset once** (remove the extra 0.08 in the viewer and 0.06 in the scene); brackets from
   `corner − normal × offset`, drawn as boxes.
6. **Handedness**: map north → −z in the scene so 3D matches map and plan view; give the top camera a north-up vector.
- Tests: panels ⊂ segment rectangle minus setbacks; panel count ≤ planner count; footprint contains all segments;
  gable fixture renders ridge without overlap; mirror test (east segment appears east in 3D).

## Phase 5 — Save everything the user enters (≈ 3–4 days, plus uploads)

### 5a. Stop losing state in-session (web only)
- Lift Size/Cost/Benefit inputs into `AnalyzeStart` (or keep steps mounted with `hidden`).
- Parent edits clear child **results**, not child **inputs** (`system-designer.tsx:31-34`,
  `financial-estimator.tsx:46-49`); remove `key={result.requestId}` remount on `BenefitEvaluator`
  (`financial-estimator.tsx:150`).

### 5b. Survive reload (web)
- After `ensureProperty` / `confirmRoof`, `router.replace('/app/analyze?propertyId=…&analysisId=…')` — also fixes the
  duplicate-property-on-reload bug (`analyze-start.tsx:170-176`).
- On load, restore the latest/matching analysis via existing `GET /properties/{id}/analyses` and jump to the right step
  (current restore only runs in a `catch`, `:84-120`).

### 5c. Server-side drafts (API)
- New authenticated `PUT/GET /properties/{id}/drafts/{analysisId}` on `ItemTable` (`apps/api/src/lib/item-table.ts`),
  ownership via `CoreService.ownedProperty`, zod-validated payload `{ designInputs, financialInputs, applicantFacts }`,
  revision-checked writes, TTL aligned with Google analysis retention (21 days for Google-sourced roofs).
- Debounced autosave from the web with a visible "Saved · 2s ago" indicator; clear on sign-out.
- Inputs remain user-reported facts; saved drafts never become benefit decisions without re-evaluation.

### 5d. Real document uploads (needs a privacy decision first)
- Private S3 bucket (SSE-KMS, block public access, lifecycle), `POST /applications/{id}/documents/upload-url`
  (presigned PUT, content-type + size limits), presigned GET for download, delete endpoint.
- Extend `addDocumentSchema` (`apps/api/src/applications/schema.ts:27-31`) with `objectKey`, `sha256`, `contentType`,
  `size`; update tracker copy (`application-tracker.tsx:136,181`).
- These are ID/bank documents: define retention, deletion-on-request, and access logging in `docs/security.md` first.
