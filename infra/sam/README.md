# AWS SAM — Core, roof and policy APIs

## Resource intent and constraints

- `Api`: regional REST API using a `v1` stage. Health is public; authenticated
  core and roof routes are implemented locally. `/solar/analyze`, the advisor,
  and original `/analyze` and `/chat` scaffold aliases remain unavailable.
  Health and CORS preflight remain public. Route throttling limits accidental traffic.
- `HealthFunction`, `CoreFunction`, `RoofFunction`, `SystemsFunction`, `FinancialsFunction`, `BenefitsFunction`, `PolicyFunction`, `PolicyPublicationFunction`, `PolicyCrawlerFunction`, `RoofRetentionFunction`, `AnalyzeFunction`,
  `ChatFunction`: Node.js 22 functions built
  from `apps/api/dist`. SAM copies **compiled JavaScript**, not TypeScript source.
  Build the API before running SAM directly; `pnpm sam:build` does this for you.
- `HealthLogGroup`, `CoreLogGroup`, `RoofLogGroup`, `SystemsLogGroup`, `FinancialsLogGroup`, `BenefitsLogGroup`, `PolicyLogGroup`, `PolicyPublicationLogGroup`, `PolicyCrawlerLogGroup`, `RoofRetentionLogGroup`, `AnalyzeLogGroup`,
  `ChatLogGroup`: stack/environment-scoped
  CloudWatch groups with a bounded retention parameter. Lambda writes JSON log
  records containing request ID, severity, duration and status, never request
  bodies, tokens, addresses or configuration values. These development logs are
  deleted with the stack; production retention requirements need review.
- Execution roles are generated by SAM with baseline logging permissions.
  `CoreFunction` and `RoofFunction` receive table-scoped DynamoDB permissions;
  `SystemsFunction`, `FinancialsFunction`, and `BenefitsFunction` receive only core-table `GetItem` for owned analysis reads;
  `RoofRetentionFunction` can query only the expiry index and conditionally delete
  expired Google roof records from the base table;
  only core property listings may query the two property indexes. `BenefitsFunction`
  may read published policy and source records with a leading-key IAM condition
  and query the active-jurisdiction index; it cannot access policy drafts or write policy data. PolicyFunction
  and PolicyCrawlerFunction have separate scoped grants to the PolicyTable and
  raw/derived prefixes of the private policy bucket. No Bedrock permissions are granted.
  Backend code checks app-client binding,
  ownership and organization membership; gateway authorization alone is not
  application ownership enforcement.
- `AnalysesTable`: the private single-table core model has `PK`/`SK`, two
  property indexes, a sparse Google roof expiry index (`GSI3`) and TTL. On-demand billing, encryption and point-in-time
  recovery protect data; deletion and replacement retain the table. Core and
  roof handlers read and write it. Google-derived previews, analyses and cache
  records carry numeric expiry and matching `GSI3` keys; manual records do not.
  Previews expire after 15 minutes, while confirmed analyses and cache entries
  expire no later than 21 days after retrieval. Reads reject expired items
  immediately.
- `RoofRetentionFunction`: EventBridge runs an hourly hard-delete sweep over
  `GSI3`, querying at most five pages of 100 expired items and deleting in
  groups of ten with conditions on type, index key and expiry. Conditional
  misses are idempotent. A remaining page or worker error raises a Lambda error;
  `RoofRetentionFailureAlarm` alarms on errors. DynamoDB TTL remains a backup
  deletion path. The nine-day gap from 21 to Google's 30-day maximum allows
  recovery from an operational incident; an alarm requires prompt response.
  Index reads are eventually consistent, so each hourly run repeats from the
  oldest expiry. Before live use, verify the alarm has a monitored notification
  destination and review whether retained PITR backups contain restricted Google data.
  This repository has no deployed table to migrate. If a table is attached to a
  future deployment, release is blocked until every existing Google-derived
  preview, analysis and cache record is either deleted or backfilled with
  `GSI3PK`, `GSI3SK` and `expiresAtEpochSeconds`, where expiry is at most 21 days
  after its original Google retrieval time. Do not restart that clock at migration.
  Verify the sweep drains those records before accepting production roof traffic.
- `RoofFunction`: server-side Geocoding and Solar API adapters, immutable
  property-bound previews, explicit building/roof confirmation and manual
  measurement fallback. Google keys are optional Secrets Manager dynamic
  references to `apiKey`, never browser or template plaintext values. The
  optional public Maps JavaScript key is separately restricted by website and API.
- `SystemsFunction`: authenticated `POST /systems/recommend` reads a confirmed
  property analysis with backend ownership checks and read-time expiry. The
  request supplies `{propertyId, analysisId, generationKwhPerKwYear, demand}`;
  demand is either measured monthly kWh or a monthly bill plus effective tariff,
  with optional sanctioned-load context. The server applies versioned design
  assumptions and returns deterministic candidates, recommendation or no-fit
  result, reason codes and the assumptions used. It does not persist a result or
  calculate policy benefits, costs or savings. Local connection rules and any
  sanctioned-load implications require review against authoritative sources.
- `FinancialsFunction`: authenticated `POST /financials/estimate` reads the
  confirmed analysis and recomputes a feasible system candidate before using
  explicit quote, tariff, self-consumption, export-rate and maintenance inputs.
  A pure versioned calculation returns 25 annual cash-flow rows, payback or no
  payback, and low/base/high sensitivities. Results are unsubsidized; export
  credit is a scenario assumption pending verified local settlement rules. No
  analysis or financial result is written to DynamoDB.
- `PolicyFunction`: admin-only `POST /admin/policy/sources` and
  `POST /admin/policy/documents` require a verified Cognito access token with
  exact `ADMIN_POLICY` or `ADMIN` group membership and verified email. Source
  registration uses an exact official host/type/jurisdiction registry, creates
  a disabled `PROPOSED` record and atomically writes a `CURRENT` pointer plus
  immutable `VERSION#00000001` snapshot. It never fetches a caller URL.
  Document uploads are restricted to 2 MB PDF or HTML, parsed into normalized
  text and deterministic cited chunks, and bound to the registered canonical
  source URL or an explicit HTTPS document URL on that exact official host.
  Multiple document URL/version series can belong to one source. The handler
  writes immutable content-addressed raw and derived
  S3 objects with conditional create, then writes a conditional document-version
  record with hashes, chunk count and exact S3 version IDs. Repeat identical
  requests return the existing record; conflicting versions return 409. An S3
  success followed by a DynamoDB failure may leave an unreferenced object, which
  can be reused by an identical retry and needs periodic operator review.
  Ingestion does not publish active policy, verify facts or calculate benefits.
- `PolicyTable`, `PolicyDocumentBucket`: isolated retained DynamoDB metadata and
  private, encrypted, versioned S3 raw/derived archive. The homeowner benefit
  Lambda has scoped read-only access to published policy and source records but
  no policy-bucket access. The bucket blocks public access and
  denies insecure transport and unconditional raw/derived object creation.
  A sparse approved-claim index (`GSI3`) supports a bounded, tentative
  cross-source comparison during candidate review; indexed evidence remains
  `UNVERIFIED` even after evidence approval.
  Admin group membership is assigned out of band;
  the stack creates groups but grants no user membership.
- `PolicyCrawlerFunction`: EventBridge checks at most ten due curated official
  sources every 15 minutes with reserved concurrency one and a conditional
  per-source lease and atomic crawl-start audit. The fetcher enforces exact official hosts, redirect and DNS
  checks, robots rules, byte and time limits. An unchanged raw response or
  cosmetic normalized-text change updates operational crawl state without
  writing another document. Meaningful text changes archive raw and derived
  versions, create an immutable change assessment, and queue exact quoted
  evidence snippets as `UNVERIFIED`. Zero-snippet changes still enter the
  document-change review queue. Failures preserve the prior archive and set a
  bounded retry state (honoring a bounded `Retry-After` on HTTP 429). A
  source requesting more than 30 days is not retried automatically; an admin
  must record a clearance reason to queue another check. The worker raises a
  Lambda error for failure or backlog.
  `PolicyCrawlerFailureAlarm` observes those errors. The alarm needs a monitored
  notification destination before production use.
  The worker monitors registered source landing URLs. New linked official
  circulars and PDFs need separate admin registration; automatic link discovery
  and review is remaining Phase 9 work.
- `PolicyFunction` Phase 9 review routes: administrators can list and curate
  proposed sources, queue an on-demand crawl, inspect a mixed evidence/change
  review queue, and approve or reject evidence and document changes. A reviewer
  must differ from the source curator. Conditional current-state transitions,
  immutable review snapshots and audit records preserve history. An approval
  means the evidence was reviewed; it does not activate or verify a subsidy
  rule. Publishing validated human-authored policy facts and rules is a
  separate required gate before the live policy pipeline can be called complete.
- `PolicyPublicationFunction`: admin-only maker-checker routes draft, submit,
  review and activate human-authored benefit rules. Every numeric value and
  eligibility, date, size or compatibility clause requires an exact archived
  official excerpt. The pending review queue uses an opaque cursor to page
  through more than 20 drafts. The API rechecks current curated source and latest document,
  then atomically writes an immutable verified policy version, activation event,
  audit and active pointer. Reviewers differ from the author and source curator.
  Cross-source replacement uses pinned prior evidence, current checks and
  deterministic source/document precedence; unresolved conflicts fail closed.
  Conditions on both source crawl revisions and the active pointer prevent a
  stale review from activating after a source changes. The initial verified-host
  registry assigns all six starter hosts authority tier 1, so higher-tier
  replacements cannot occur until an independently verified host is added.
- `BenefitsFunction`: authenticated `POST /benefits/evaluate` loads an owned,
  unexpired confirmed roof, recomputes the selected feasible system, then reads
  only active verified policy versions relevant to the declared jurisdiction.
  Applicant facts are user declarations, not proof of entitlement. Current crawl
  state and cited document identity control freshness; missing or changed
  evidence makes a rule unavailable. The engine evaluates at most 16 relevant
  rules with deterministic stacking and returns citations, source check times,
  incomplete coverage, and no amount when no current verified rules exist.
  Index pagination and an over-limit relevant catalog fail closed. The first
  release does not assert policy coverage completeness. Same-source documents
  share a conservative source-level freshness status, so one superseded citation
  can temporarily suppress another rule from that source.

Names and tags use the stack/environment parameters. No cloud credentials or
Google keys are embedded. API Gateway execution/access logging is not enabled
here because its regional account-level logging role must be reviewed with the
target account; Phase 0 observability is Lambda/CloudWatch logging only.

## Cognito resource intent and constraints

- `Api.GatewayResponses`: fixed-origin CORS and sanitized structured errors
  even when authorization fails before Lambda. They are defined inside the SAM
  API so its generated OpenAPI definition owns the gateway responses.
  Default HTTP status codes are preserved; origins are never reflected from
  untrusted request headers. Lambda proxy responses use the same validated
  `API_ALLOWED_ORIGIN`, not merely the API's OPTIONS/preflight configuration.
- `ProfileFunction`, `ProfileLogGroup`: protected `GET /me`, compiled identity
  verification with JWT/app-client binding and bounded Cognito `GetUser` calls.
  The response is identity context only, not ownership or tenant membership.
  `COGNITO_USER_POOL_ID`, `COGNITO_CLIENT_ID` and `COGNITO_REGION` are supplied from
  this stack. `GetUser` uses the user's access token and does not evaluate IAM;
  no Cognito admin/read IAM grant is added to the execution role. SDK clients and
  trusted JWKS verifiers are reused, but user responses/tokens are not persisted.
- `UserPool`: retained identity directory with verified email, strong password
  requirements and optional software-token MFA. Managed login v2 uses the
  Essentials feature plan; review costs before creation. Pool/schema changes can
  require migration and must not silently discard identity data.
- `UserPoolClient`: **public**, no secret, authorization-code flow only; 15-minute
  access/ID tokens, one-day rotating refresh tokens and token revocation. The
  incompatible `ALLOW_REFRESH_TOKEN_AUTH` flow is deliberately not enabled.
  Organization attributes are read-only to this client; users cannot self-assign
  broker membership or organizations.
- `UserPoolDomain`, `ManagedLoginBranding`: globally unique developer-chosen prefix
  and per-client branding, required for functional managed login v2. Exact
  callback/logout URLs come from `ApplicationOrigin`; never use arbitrary return
  URLs or silently swap a development origin into production.
- `HomeownerGroup`, `BrokerGroup`, `PolicyAdminGroup`, `AdminGroup`: identity-display groups, not database ownership
  or IAM permissions. Broker membership is administrator-assigned. No identity
  pool or browser AWS credentials are created.
- `GoogleIdentityProvider`: disabled by default. Enabling it requires a Google web
  client ID and a Secrets Manager ARN with `clientSecret`; the secret is resolved
  by CloudFormation, not shipped to the browser. Keep the secret in the deployment
  region and register Cognito's `/oauth2/idpresponse` URL with Google first.

No deployment or live login/federation/Google test has been performed. Template
invariant tests run as part of `pnpm check`; they do not establish service-schema
validity, correct IAM permissions or working live authentication. Public outputs
provide configuration identifiers only, not credentials.

## Local commands

From the workspace root, after dependency installation:

```bash
pnpm sam:validate
pnpm sam:build
pnpm sam:local
```

SAM validation requires AWS SAM CLI and cfn-lint. Build does not require Docker
for these precompiled bundles. Local invocation requires Docker. Test health at
`http://127.0.0.1:3000/health`; local SAM routes do not include the deployed `v1`
stage prefix. Use JSON bodies for POST scaffold routes.

Tool installation is not automatic and should use an isolated environment with
approval. The current development environment lacks SAM CLI, cfn-lint and
cfn-guard. Local checks cover YAML syntax, compiled handlers and references;
CloudFormation schema validation is configured in CI but has not been run
locally. A read-only `aws cloudformation validate-template` in `ap-south-1`
succeeded, but this does not replace SAM schema/lint or deployment validation.
Security/compliance and account-aware checks have not been performed.

## Deployment gate

This is not a production-ready backend. Do not run `pnpm sam:deploy` until the
AWS account, region, stack, permissions, validation and intended costs are
confirmed. No deployment was performed during Phase 0 setup.

`pnpm sam:deploy` references the built `.aws-sam/build/template.yaml`. A successful
application build does not prove CloudFormation or IAM deployability. Preserve
the table's retention policies and validate infrastructure separately before
creating or updating a stack.
